# 新项目裁剪与交付验收

## 20. 新项目采用与交付验收

### 20.1 裁剪原则

1. 保留分层、配置、错误、日志、生命周期和测试基础。
2. 在 ADR 中选择 PostgreSQL + Drizzle 或 MongoDB + Mongoose，删除另一种空实现。
3. 普通缓存需要替换后端时使用 Keyv，并只安装选定 Adapter。
4. 只有需要 Redis 原生命令时增加独立 Redis client，不为了技术完整强制启用。
5. 轻量进程内调度按需使用 Croner；持久异步任务按需引入 BullMQ 并明确 Redis/PostgreSQL 后端；有 CPU 密集任务才引入 Tinypool。
6. 简单 JWT/固定角色使用 Hono JWT；只有复杂 RBAC/ABAC 和动态策略才引入 Casbin。
7. 使用 Zod 做边界验证，使用 es-toolkit 代替重复通用工具。
8. 删除示例业务后同步删除路由、装配、配置、迁移、测试和文档，不能留下半可用入口。

### 20.2 架构验收

- [ ] Controller 不含业务和持久化细节，Service 不 import Hono。
- [ ] 依赖通过构造函数注入，没有全局可变请求状态和业务层 Service Locator。
- [ ] DTO、领域类型和数据库类型分离，内部字段不会意外成为 API。
- [ ] 主数据库选型明确，没有无事实源的双写。
- [ ] Keyv 与 Redis 的职责、连接、key、序列化和失败策略分别说明。
- [ ] 所有资源有创建者、所有者和关闭路径。

### 20.3 配置与安全验收

- [ ] smol-toml 加载本地和重复 `--config`，覆盖顺序有测试。
- [ ] 进程环境 > `.env` > TOML 的秘密优先级有测试，`.env` 不覆盖进程环境。
- [ ] Zod 拒绝未知键和非法配置，当前 driver/Adapter 的必要 URL 缺失会启动失败。
- [ ] 秘密、真实连接 URL 和本地文件未提交，日志和错误响应已脱敏。
- [ ] 认证、权限、资源归属、CORS/CSRF、请求限制和限流按路由验证；JWT 与 Casbin 职责没有混淆。

### 20.4 数据与可靠性验收

- [ ] 唯一性、幂等和事务由真实数据库测试，不依赖 JS 预查询或实例锁。
- [ ] 迁移可审计，兼容滚动发布，备份和恢复经过验证。
- [ ] Keyv TTL、namespace、错误、缓存失效和 Adapter 契约经过测试。
- [ ] Redis 原子操作、锁释放、重连和降级经过测试，无无界 key 和危险全库操作。
- [ ] BullMQ（若启用）后端迁移、重试、幂等、最终失败恢复、保留策略和 Worker 关闭经过真实后端测试。
- [ ] 超时传递到下游，重试有上限且操作幂等，关闭能排空请求并释放连接。
- [ ] 多实例不会丢身份、权限、配额或业务一致性；Croner 多副本防重、时区和错过执行策略经过验证。

### 20.5 工程交付验收

- [ ] `npm run dev` 使用 tsx watch，生产 build/start 已验证。
- [ ] format、lint、typecheck、test、build 在干净环境通过。
- [ ] 真实数据库、Keyv Adapter、Redis 和 E2E 测试按启用范围通过。
- [ ] Tinypool（若启用）验证开发/生产 Worker 路径、池上限、超时和关闭。
- [ ] Casbin（若启用）model/policy/Adapter 版本、策略刷新、审计和多实例一致性有明确方案。
- [ ] Day.js 插件统一初始化，Instant/纯日期、时区、DST 和 Clock 测试符合约定。
- [ ] README、API 文档、配置示例、ADR 和部署回滚说明与实现一致。
- [ ] 未执行或未完成的项目明确记录，不以文档描述冒充验证结果。

## 附录 A：ADR 最小模板

```md
# ADR-NNNN：决策标题

- 状态：提议 / 已接受 / 已替代
- 日期：YYYY-MM-DD
- 背景：业务需求、约束、当前问题
- 决策：选定的技术与边界
- 备选：至少一个可行替代及未采用原因
- 数据：事实来源、事务、迁移、备份和一致性
- 失败：超时、重试、降级、恢复和对账
- 安全：权限、秘密、隐私和滥用边界
- 验证：单元、集成、并发、E2E、发布与回滚
```

## 20.6 新项目文档落地顺序

采用手册时建议形成以下真实项目文档：

| 文件 | 内容 | 维护时机 |
| --- | --- | --- |
| README.md | 当前选型、安装、Compose、开发、测试和部署入口 | 任何工作流变化 |
| docs/api.md | 当前 HTTP 契约与示例 | 每个 API 变更 |
| docs/adr/ | 数据库、认证、缓存、任务等决策 | 重要方案变化 |
| config.example.toml | 非秘密配置和注释 | 每个配置变化 |
| .env.example | 秘密变量占位和用途 | 每个秘密来源变化 |
| compose.dev.yaml | 当前选型的可丢弃开发依赖 | 依赖或版本变化 |
| docs/deployment.md | 迁移、发布、回滚、健康检查和恢复 | 部署行为变化 |

不要保留与实际项目无关的空文档。文档中的命令必须在干净环境验证，示例中的 `order` 等业务替换为真实模块。

## 20.7 交付证据模板

每次交付记录：

```md
## 变更
- 行为：
- 配置：
- 数据库/缓存兼容：
- 回滚：

## 验证
- [ ] format / lint / typecheck
- [ ] Vitest unit
- [ ] Vitest integration（涉及真实依赖时）
- [ ] Vitest e2e
- [ ] 构建产物 smoke
- [ ] Docker Compose 干净环境启动
- [ ] 多实例/滚动发布（涉及共享状态或迁移时）

## 未验证与风险
- 明确列出未执行项目、环境和剩余风险。
```

## 20.8 最终完成定义

只有代码、配置、迁移、文档和测试共同完成，才算模块交付。没有实际运行测试不得勾选；只通过单元测试不能宣称数据库、E2E、Smoke 或多实例已经验证。
